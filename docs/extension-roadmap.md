# LX 矩阵浏览器插件 · 产品设计与路线图

> 负责人视角的完整设计。目标只有一个：**把成员的互推从"靠自觉"变成"有系统"，形成流量矩阵。**

## 一、为什么要做流量矩阵

X（Twitter）的推荐算法对发帖后**第一个小时内的互动密度**极其敏感：早期的点赞、回复、转发会把内容推进更大的流量池。单个蓝V冷启动很难，但 N 个成员互为"第一批互动"，每个人的内容都能稳定越过冷启动阈值——这就是矩阵的本质：

```
成员发帖 → 其他成员第一时间互动 → 算法判定为优质内容 → 推给更大流量池
   ↑                                                        ↓
   └────────────── 每个人涨粉、涨曝光，更愿意发帖 ←──────────────┘
```

这个飞轮要转起来，有三个卡点，全部是**工具问题**而不是意愿问题：

| 卡点 | 现状 | 插件要解决成什么样 |
| --- | --- | --- |
| **不知道**：成员发了帖，别人不知道 | 靠微信群里手动丢链接 | 新帖自动进入每个人的"待互动队列"，浏览器角标提醒 |
| **记不住**：知道了但忘了去互动 | 没有任何记录 | 每条帖子有"已互动/待互动"状态，闭环可见 |
| **看不见**：刷推时遇到成员内容认不出来 | 无标识 | 在 x.com 页面上给成员推文打"LX"标，顺手就互动了 |

## 二、产品形态总览

插件 = **popup 面板**（任务队列 + 成员监控）+ **后台轮询**（角标提醒）+ **x.com 内容脚本**（现场识别与自动打卡）。后端是已有的 Next.js 站点（审核、令牌、快照、动态流都已就绪）。

身份模型沿用现状：成员在网站上用 Twitter OAuth 登录 → `/extension` 页面生成 `ext_` 令牌 → 插件用令牌调 API。**只有已通过审核的成员能用**，这本身就是矩阵的门槛与权益。

## 三、分期规划

### Phase 1 — 看见（已上线）

- 成员动态流：聚合所有成员近期原创推文，"去互动"一键跳转。
- 成员监控：每人今天发没发帖（快照差值），未发的排前面。

> 解决了"不知道"的一半：打开 popup 能看到。但不打开就什么都没有，且互动没有闭环。

### Phase 2 — 闭环（本期实现）✅

核心指标：**互动覆盖率** = 已互动人次 / (成员推文 × 在册成员)。本期所有功能都为这个数字服务。

1. **互动打卡闭环**
   - 每条动态对"我"有 `engaged` 状态，后端 `tweet_engagements` 表记录（谁 × 哪条推文）。
   - popup 里"去互动"跳转后可一键"标记已互动"；待互动的排前面、已互动的变灰。
   - 自己的推文不进自己的队列（标记为"我的"）。
2. **角标提醒（badge）**
   - 后台 service worker 每 30 分钟拉一次动态流，角标显示**近 24 小时内还没互动的成员推文数**。
   - 数字归零 = 今天的矩阵任务清完，强化打卡习惯。
3. **x.com 现场识别 + 自动打卡**
   - 内容脚本在 x.com / twitter.com 时间线上识别成员推文，打上"LX 矩阵"标。
   - 在成员推文卡片内点击 点赞/转发/回复 时，自动上报打卡——**顺手互动零成本记录**，不需要回到 popup。
4. **个人覆盖率**
   - popup 头部常驻："今日待互动 N · 已互动 M"。

### Phase 3 — 放大（下期）

- **互动率排行**：按周统计每个成员的互动覆盖率，popup / 网站展示排行榜，做社群荣誉体系（与群规的考核挂钩）。
- **管理端看板**：admin 页看全群覆盖率趋势、谁长期搭便车（只收互动不付出），为清退提供数据。
- **发帖时机建议**：基于全群互动活跃时段，提示"现在发帖矩阵响应最快"。
- **周报**：每周生成矩阵战报（总曝光、总互动、最佳推文），可一键转发到微信群。

### 非目标（明确不做）

- ❌ 自动点赞/自动转发机器人 —— 违反 X 平台规则，且互动质量为零，反而伤号。插件只做"提醒 + 记录"，互动永远由真人完成。
- ❌ 抓取登录态私有数据 —— 一切数据来自公开 API（xapi）与成员自己的打卡上报。

## 四、本期技术设计（Phase 2）

### 数据

```sql
CREATE TABLE tweet_engagements (
  registration_id BIGINT  REFERENCES twitter_registrations,
  tweet_id        TEXT,    -- member_tweets.tweet_id
  source          TEXT,    -- 'popup' | 'x.com'（来源分析用）
  created_at      TIMESTAMPTZ,
  PRIMARY KEY (registration_id, tweet_id)
);
```

### API

| 接口 | 变化 |
| --- | --- |
| `GET /api/feed` | 每条 item 增加 `engaged`（我是否已互动）、`own`（是否我自己的推文）；响应增加 `summary { pending, engagedToday }` |
| `POST /api/engagements` | `{ tweetId, engaged, source }` 打卡 / 取消打卡；拒绝给自己的推文打卡 |
| 鉴权 | 抽出 `app/lib/memberAuth.ts`：ext 令牌或 OAuth session → 解析成 registration id（feed/members/engagements 共用） |

### 插件

| 模块 | 职责 |
| --- | --- |
| `background.ts`（MV3 service worker） | `chrome.alarms` 每 30 分钟拉 feed → 设角标；作为消息中枢供 content script 取成员名单、转发打卡请求（content script 不直接持有令牌请求逻辑，统一走后台） |
| `content.ts` | x.com 时间线 MutationObserver：识别成员推文 → 注入"LX 矩阵"标；监听卡片内 点赞/转发/回复 点击 → 自动打卡 |
| `connect.ts` | 站点 `/extension` 页内容脚本：接收页面 `postMessage` 的令牌 → 写入服务地址 + 令牌（零配置接入），回发 `connected` 让页面确认 |
| popup（React） | 待互动队列（pending 优先）、打卡按钮、覆盖率头部；服务地址默认预填生产域名 |

构建：vite 多入口（popup html + background + content），content/background 保持零运行时依赖（仅 `import type`），避免产物携带跨 chunk import（MV3 content script 不支持 ES module）。

## 五、度量

- **北极星**：周互动覆盖率（目标 ≥ 70%）。
- 辅助：角标点击率、自动打卡占比（x.com 来源 / 全部）、成员日发帖率。
- 数据已具备：`tweet_engagements.source` 区分来源，`tweet_snapshots` 提供发帖率。
